# 本机联调探针（只用于开发）

把一个命令解释器编进 `Payload.dll`，在真实的专服进程和客户端进程里读写对象、调用函数、跟踪事件。用它可以不靠玩家试玩就看到局内状态。**带探针的构建不得安装给玩家**：构建标记里有 `dev-rig=1`，联调脚本结束时会把 Steam 目录恢复成联调前的组件。

## 构成

- `Rig.hpp`、`main.patch`：探针本体和两侧 ProcessEvent 钩子里的接入点。构建时加 `-IncludeDevRig`，进程命令行带 `-BrtRig` 才工作。
- 联调脚本在 `C:/BrtWork/QA/artifacts\brt-dev\`：

| 脚本 | 作用 |
| --- | --- |
| `rig.ps1 up` / `down` / `status` | 起档案服务（存档副本）、专服、客户端并装入探针组件；`down` 结束进程并恢复原组件。`BRT_RIG_DLL` 环境变量可指定要装的 DLL，默认用开发树 `main\bin\Payload.dll`。 |
| `join.sh [服务端预置命令…]` | `up` 之后等客户端进到选角界面；登录界面的空格由脚本投递。 |
| `rc.sh <server\|client> <等待秒> <最多行> 命令…` | 发命令并取回新增输出。 |
| `shot.ps1` | 只截游戏窗口自身的画面到 `run\.jpg`（窗口被遮挡也能截，不读屏幕上其他内容）。 |
| `key.ps1 <十六进制键码>` | 向游戏窗口投递一次按键。 |
| `dis.sh <起RVA> <止RVA>` | 反汇编零售主程序的一段。 |
| `build.ps1` | 开发树增量构建，约 1 分钟。 |

开发树是 live37 构建目录的副本：`.scratch\brt-dev\main\source`。完整流水线构建见 `.scratch\brt-dev\build-rig38.ps1`。

## 命令

命令写进 `Win64\logs\BRT-rig-<side>.cmd`，输出在同目录 `.out`，每行开头是探针启动后的毫秒数。对象可以写 `#索引`、别名（`pc`、`pawn`、`ps`、`hud`、`gm`、`gs`、`world`）、`cdo:类名片段`，或全名片段。

| 命令 | 说明 |
| --- | --- |
| `objs <类名片段> [全名片段]` | 列出类继承链含该片段的现存对象；Actor 附带拥有者和位置。最多 120 行。 |
| `props <对象> [属性名片段]` | 按反射打印属性。 |
| `set <对象> <属性> <值>` | 写基本类型属性。 |
| `funcs <对象> [片段]` | 列出可调用的函数名。 |
| `call <对象> <函数> [参数…]` | 经 ProcessEvent 调用，打印出参和返回值。结构体参数用逗号分隔。 |
| `exec <对象> <函数>` | 打印该函数原生入口的 RVA，配合 `dis.sh` 用。 |
| `trace <片段>` / `trace stack <片段>` / `trace mute <片段>` / `trace off` | 记录名字含该片段的事件；`stack` 额外打印主程序内的返回地址。 |
| `watch <对象> <属性,属性>` / `unwatch` | 属性变化时记一行。别名每次轮询重新解析。 |
| `tp <Actor> <目标Actor> [抬高]` | 把 Actor 传到目标位置。 |
| `key <十六进制键码> [毫秒]`、`click L\|R` | 向游戏窗口投递输入。 |

## 已知限制

- 没有接房间服务，房主身份不成立：写档、首次菜单、GPT 的客户端模块（要求 `InScope`）在联调里都不工作。
- 投递的按键能到界面（登录的空格可用），到不了局内操作（钩索、F、Esc 都无效）。局内输入需要游戏窗口在前台，会抢玩家的键鼠，先问玩家。
- 没找到可靠的击杀办法：服务端调 `ServerSuicide(0)` 无效，客户端调过一次后专服进程直接消失且没有转储，`ApplyDamage` 无效。目前只能等机器人打死。
- 专服的 `ServerDebugLog` 输出不进标准输出，`[LATEJOIN]`、`[CAM-FIX]` 看不到。
- 客户端每次启动窗口会弹到前台。上游的 `PressSpace()` 用全局 `SendInput`，窗口不在前台时空格会落到玩家当前的程序里。
