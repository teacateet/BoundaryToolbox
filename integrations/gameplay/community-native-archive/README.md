# 本机 PvE：把房主档案写进原生角色档案

原版专服在玩家登录后向后端读取档案，由回调 `0x15BA210` 把每名干员的枪械配件、涂装和角色外观写入 `APBPlayerState+0x700` 的逐角色档案。出生前 `0x15BD760` 取这份档案，再按预订槽位覆盖物品 ID。本机专服没有后端会话，这份档案一直是原厂默认，所以挂载能带对、配件和外观带不进局。地址均为 Steam Build 14530908 的 RVA。

本模块在原生 `ServerConfirmRoleSelection` 执行之前，对已核验的本机房主做一件事：读出这名干员当前的主副枪（档案条目和 `+0x6C0`、`+0x6E0` 两张预订表），向本房档案服务取这两把枪的保存配置，再用回调自己调用的原生写入函数写进该干员的档案条目。之后建枪、复制到客户端都由游戏完成。

| 写入内容 | 原生函数 |
| --- | --- |
| 查角色条目 | `0x15AEB20`，元素 0x110，值在 +8 |
| 取或新建枪条目 | `0x166D980`，枪表在值 +0xB0 |
| 整枪外观与涂装 | `0x16615C0` |
| 逐槽配件 | `0x16615B0`，槽号 1 至 10 |
| 配件皮肤和特殊槽 | `0x16614D0`，类别 1 和 4 |
| 配件涂装 | `0x1661560` |
| 挂饰 | `0x16613F0` |
| 角色服装、涂装、臂章、头饰 | 值 +0x90、+0xA8、+0xA0、+0x98 的四个名称 |

调用顺序与原生转换函数 `0x1791F00` 对每把枪的处理一致。明确卸空的槽照原样写入空名称。角色外观只写本人保存过的字段。映像版本不符、不是本机房主、角色不在本人菜单或原生条目不存在时不做任何写入。

出生后的逐枪核对改为只读：不再对已经创建的枪调用 `InitWeapon`，只把 `GetPBWeaponPartSaveConfig()` 与期望配置比较，并记下第一处差异。

专服的 `Win64/logs/BRT-archive-<PID>.log` 记录 `confirm`、`weapon`、`character`、`written` 和 `born-weapon`。`written` 只说明写入函数已返回；配件是否进局，看同场 `born-weapon same=1` 和玩家画面。

构建时在 `community-stack/build-payload.ps1` 加 `-IncludeNativeArchive`。本模块的补丁排在 `community-owner-birth` 之后。[原生调用](NativeArchive.hpp) · [差异](main.patch)
