# 同一 PvE 房间的房主重连

旧社区程序按房间领取一次首次选角数据。即便房主已经断线，同一房间第二个控制器仍会收到 HTTP 409。更新后，房主首次进入和重新连接时，选角会读取当前军械库。首次请求返回之前发生重试，同一个连接会拿到先前那份快照。提交六名干员的装备后，同一控制器再次收到登录事件也会保留当前选择。

专服比较引擎分配的控制器和网络连接对象，以及各自的对象代次。前一连接仍属于原控制器期间，其他控制器的请求会被挡住。如果新登录恰好先到，专服会在原有游戏线程里等待上一连接解除。房主尚未选角时，新控制器承接本房上一次有效登录并取回新的 36 个槽。玩家先完成了选角时，专服保留玩家的选择。[连接交接](Reconnect.hpp) · [登录先后的处理](Retry.hpp)

房主在登录回调前或读档期间选好了干员，专服仍会为这个连接登记出生配件。已经选角的玩家继续使用自己的选择。尚未选角时会收到六名干员的预订。登录分别记录选角处理和出生登记的结果，重复回调只补尚未完成的工作。已在两套社区源码编译，并在完整登录函数上验证选角先后、普通预订、登记失败再试和连接失效。[登录入口回归](tests/selected-login.ps1)

工具箱正式服务已包含本次增量。社区源码依次应用选角、武器出生、钩锁观察以及本目录对应的重连补丁。v0.8.4 和 main 的实际登录代码都经过 MSVC x64 编译。[工具箱服务增量](toolbox-reconnect.patch) · [v0.8.4](v084-reconnect.patch) · [main](main-reconnect.patch)

验证中，首次登录读到蜂巢，改装后重复相同请求仍拿到蜂巢。新控制器经过交接后读回宇宙麻雀，6 名干员的 36 个槽全部与原版档案接口一致。另一个用于出生的连接从第 1 条生命连续读到第 5 条。错误房主、错误房间凭据、已经用过的前任，以及没有交接凭据却企图在当前生命打开首次菜单的情况均被拒绝。[结果](verification.json)
