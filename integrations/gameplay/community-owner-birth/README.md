# 原版普通房：当前出生实体的枪械改装

2026-11-23 的 OSS 普通房已进入比赛。工具箱收到 2 份非空军械库回包，每份 6 名干员、每人 6 个槽。房主初始选角快照已取到，档案服务没有收到出生请求。房间连续观察到 6 次出生，每次首帧约 33–51 ms、2 把枪、未持枪、占有尚未确认，却一律以 `pawn-not-in-unused-state` 结束；这个旧日志不能区分究竟是哪一个条件。

[维护补丁](main.patch)适用于已装 live35 补丁的社区 main，应用后将 [OwnerBirthGate.hpp](OwnerBirthGate.hpp) 复制到 `ProjectReboundMainDLL/BrtInventory`。

- 等待反向控制器关联、角色存活、游戏恢复或原生选角状态，仍使用原 250 ms 出生窗口，并额外限制实际经过时间。确认占有、瞄准、开火/发射计数变化、死亡、其他控制器接管、会话更换及超时会终止；每次等待原因变化和终止原因分别记录。用本局已认证的控制器、PlayerState 和网络连接确认房主，不用 `IsLocalController` 推测网络身份。
- 从原作 Blueprint 可读的 `PossessedCharacterId` 取当前干员，使用 FName 相等判断，按出生实体的蓝图类再次核对。原生库存持有者、创建时间和实际枪械 ID 都必须匹配。军械库的默认枪与手选型号不一致时，以手上这条生命已经生成的枪为准。
- 档案查询和应用分开。得到明确干员/库存后可先读配置，本命只取一次。只把返回的改装交给相同 ID、同一实例且未持用的那把枪。另一把枪的改装验证独立进行；空槽不生成武器。一把枪或角色变更后不使用旧快照。此模块不会替换武器型号、写玩家档案或创建角色装备。
- `newborn-plan-returned` 表示 HTTP 调用返回；`newborn-weapon ... parts-readback=1` 表示对应服务器实体读回部件。需在 Steam 普通局看见同枪正确瞄具及皮肤，才能验收。角色服装的 `RefreshCharacterSkin` 是表现接口；没有证明此调用可设置权威配置并向玩家复制，本补丁不据此声称角色外观已修复。

[回归](owner-birth.test.cpp)覆盖刚生成到就绪的连续状态、暂态和终止条件重叠时的优先级，以及手选、外来干员和空枪 ID。已以实际 live35 的 SDK、公共游戏类与 MSVC x64 编译修改后的 `Birth.cpp`。这些检查不是原版普通局的验收。
