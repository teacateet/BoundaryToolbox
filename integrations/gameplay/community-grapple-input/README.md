# 本机 PvE 钩索第二次按键

玩家在同一条命里看见冷却结束，第二次按键时没有出绳。社区服的首生和稍后入场代码会解除移动、视角输入限制。发行版和主线的普通角色、装备及输入业务都未找到第一次使用后屏蔽机动键的逻辑。零售游戏处理按键、准备和发射的内部实现没有随这两套社区源码发布。

补丁在本机 PvE 原有角色界面回调读取玩家的 `ActivateMobility` 映射。每次只看该动作对应的键，读取按下和松开的游戏帧，并记录角色界面实际收到的准备、取消、发射、重置通知。每条记录从角色的当前机动槽重新取装备，同时读游戏报告的冷却与可用状态。换命后重新计数。游戏的 `Saved/Logs/BRT-grapple-input.log` 保存最近一次运行，最多 257 行，同时发送到社区客户端的普通日志。

| 日志 | 如何读 |
| --- | --- |
| `life`、`frame`、`press` | 当前客户端的生命序号、引擎帧号、这条命里观察到的按下帧数。同一帧内的多个映射键合并，准备通知也可能先于该帧的按键读数。 |
| `event=mapped-key`、`edge` | 1 为按下，2 为松开，3 为同帧出现二者。这个读数只确认玩家控制器看到当前映射键的变化。带组合键、菜单焦点或更高优先级绑定时，实际动作是否获准还要看随后的原生通知。 |
| `event=prepare/cancel/launch/reset` | 角色界面收到了相应的原生通知。发射通知与专服收到发射、游戏画面是否出绳分别取证。 |
| `mapped`、`down` | 此帧游戏选项返回的不同有效键数，以及至少一个绑定键是否仍按住。0 表示没有有效键，-1 表示选项子系统不可用。日志省略按键名。 |
| `module`、`slot` | `grapple` 表示机动槽是属于当前角色的钩索，`none` 为空或已经失效，`other` 为其他机动装备，`foreign` 表示钩索拥有者与当前角色不符。槽编号在当前生命内有效。 |
| `phase/cool/enabled/active` | 当前钩索原生阶段（0 待命、1 发射中、2 锁定、3 回收中）、冷却位、启用位、激活位。-1 表示没有可读取的本机钩索。 |
| `cooled/allowed/using` | 角色此时是否报告冷却完成、允许使用、正在使用钩索。 |

同一 `life` 中，若第一次出现 `mapped-key → prepare → launch`，第二次仅出现 `mapped-key`，可查看第二次按下时的 `module`、`cooled`、`allowed` 和 `phase`。若 `prepare` 紧接 `cancel`，则原生界面至少已进入准备阶段。没有相应记录的帧仍可能发生采样间隔内的事件。两次都出现 `launch` 时，需要与专服同一生命的现场记录对照。

先应用准星及雷达补丁，再将 `GrappleInput.hpp` 复制到角色界面源文件的同一目录，应用对应版本的 `v084.patch` 或 `split.patch`。客户端需实际包含改动并由工具箱带 `-BrtLocalPveUi` 进入原生易、中、难 PvE 房间，才会在下次手动操作产生记录。

`./verify.ps1 -OutputDir <临时目录>` 使用 MSVC 编译并执行同一个观察器，覆盖首发、第二按被拒、准备后取消、长按、改键、换槽、死亡和重生。加 `-CombinedUi <已应用准星及雷达的界面 CPP> -OriginalModule <含 SDK 的完整社区模块目录> -Layout v084` 或 `split`，还会分别编译修改前后的真实界面模块，并检查对象符号。[验证回执](verification.json)
