# 本机 PvE 出生时的武器配件

这组增量源码把房主保存的主副武器配件接到社区服的正常登录和出生流程。每把枪分别处理 10 个改装槽、各槽皮肤和涂装、武器饰品，以及原作单独存放的机匣外观。选角预订负责确定武器和左右挂载，这里只处理这个已登录房主拥有的实际武器对象。[武器配置与游戏回读](Birth.cpp) · [先行的选角集成](../community-inventory/README.md)

工具箱正式工作树已包含只读的本机房主装备查询。它复用已有的房间凭据、账号校验和档案读取，既有出生连接可同时使用。其他含有 `login-menu` 的工作树可应用工具箱增量。社区源码在对应版本的选角补丁上继续应用出生补丁。每个补丁包含正常业务调用位置和编译项。[工具箱增量](toolbox-birth-plan.patch) · [社区 v0.8.4 增量](v084-birth.patch) · [社区 main 增量](main-birth.patch) · [选角补丁和次序](../community-inventory/README.md)

登录时登记这位房主。服务器随后在监听房间的 `LateJoinManager::Tick` 上检查正常出生；社区自己调用的 `RestartPlayers` 和 `ServerQuickRespawn` 返回时也立即检查。角色真实死亡后换了 Pawn，或者身份相同的控制器在死亡计数增长后直接换 Pawn，都可以打开下一次出生检查。服务器根据本局准入角色、角色蓝图类、两把原生枪的 ID 以及当前房主本人的已存主副槽辨认装备。相同模型可能对应多个角色，保留歧义时跳过。[角色匹配与来源](RolePaths.hpp)

首次检查若晚了一帧，服务器会核对角色确实创建于上次看见该玩家尚未出生之后。仅给同一个角色最多 250 毫秒等待选角和主副枪到齐；枪也不能早于角色创建。客户端确认占有、开始射击或瞄准等情况都会结束等待。已持用、已部署或正在换弹的枪不会重新初始化，另一槽仍会独立检查。只有所有已装备的武器都从实际对象读回了保存的部件、各槽外观和饰品，才记整套成功。[出生时机检查](BirthWindow.hpp) · [核对实际武器配置](Birth.cpp) · [延迟到齐与读回测试](BirthWindow.test.cpp)

| 专服日志 | 可判断的状态 |
| --- | --- |
| `observed-birth ... pawn-age=... inventory=... holding=... acknowledged=...` | 每条观察到的生命记录一行，含出生年龄、实际库存数量、是否已有持枪和占有确认 |
| `newborn-weapon life=1 slot=2 submitted=1 parts-readback=1` | 本次调用后，第 1 条生命的副枪已读回相同的部件及外观 |
| `submitted=0 parts-readback=1` | 武器原有配置已符合保存值 |
| `submitted=1 parts-readback=0` | 已调用初始化，本次同步回读尚未匹配 |
| `newborn-slot-skipped ... reason=weapon-in-use` | 此枪在手中，或已经进入部署、瞄准或换弹等使用状态 |
| `newborn-skipped ...` | 记录错过时机、角色或武器身份有歧义、档案未就绪等原因 |

两个版本均在独立干净副本上依次应用选角、出生和钩锁观察补丁，再使用 MSVC x64 编译同一份登录源码、武器出生源码和钩锁观察源码。C++ WinHTTP 与正式工作树的本机档案服务测试覆盖 6 名常规干员，并验证改装后 DMR 的金机匣、重枪管和快装弹匣，以及 FOP 的红机匣和微型红点。零售专服是否能在每种出生路径及时取得武器，还需要实际房间的日志。[联合编译与前后对照](verification.json)
