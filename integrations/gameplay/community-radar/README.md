# 本机 PvE 的头顶标记和小地图

玩家用探针或瞄准标出敌人时，头顶会先出现本方标记。社区客户端现在会检查同一视口的左下小地图。原生雷达尚未画出这个点时，代码调用原版小地图的画布和点迹 Blueprint，按游戏自己的投影画一次。原生点接手、标记消失、角色死亡、雷达失去信号或视口销毁时，补充的点会从画布移除。[实现](MarkedHeadRadar.hpp)

当缓存仍写着「未标记」或保留旧坐标时，已通过当前视口、阵营、遮挡、距离检查的头顶标记会按本帧位置投影。缓存图标缺失时使用该对象的原生小地图图标；缺少图标、标记已经消失和本地角色均保持不显示。

修正仅在工具箱打开的本机 PvE 中启用，并核对游戏复制给客户端的难度模式、当前角色和本地控制器。补点取自原版已显示且没有遮挡的敌方角色头顶标记，包括原版的感应、侦察和目视标记。原始数据限定世界距离为 5,000 个单位，水平 UV 为 0 至 1，垂直 UV 为 0.125 至 0.75。实现使用当前小地图实例上的这三项数值。在原生雷达尚未捕获目标时，使用头顶标记此刻的位置。每个可见目标最多增加一个小地图控件。[受控界面测试](tests/result.json)

两份补丁接在同目录的社区角色界面回调和相应的 Visual Studio 项目中。先应用社区麻雀瞄环修正，将本目录的头文件放在同一个回调源文件旁，再应用相应分支的雷达补丁。工程会编译原版的两个 UMG 实现，以调用实际 Blueprint 的画布和刷新方法。[V0.8.4 补丁](v084.patch) · [拆分版补丁](split.patch)

验证脚本在一个新目录里应用两层补丁，编译完整客户端业务文件和两个具体 UMG 翻译单元，检查业务对象引用和 SDK 对象定义的符号，并合成静态库。行为回归运行相同的 C++ 修正和可控的本机界面对象，覆盖空捕获表、原生点接管、回收池、视口归属、距离、消标和死亡。Steam 零售客户端仍待实局验收。[编译验证](verify-source.ps1) · [行为回归](tests/verify.ps1)

本机 PvE 的 `Saved/Logs/BRT-local-ui.log` 只在本人角色进入支持的房间后打开。每项仅记录第 1 次和第 16 次，共不超过 52 行。雷达记录原有公开头标、投影、原生点和画点分支；挂载记录本人左右肩选择、归属和第一人称组件收集；麻雀瞄环记录识别、隐藏和恢复。不另遍历角色，不记录目标身份、坐标、按键或令牌。这些是整场累计的处理次数，不能据此判定玩家在画面上看到了修复。
