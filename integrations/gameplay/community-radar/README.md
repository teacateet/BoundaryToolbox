# 本机 PvE 的雷达：弹药箱和已标记角色

19.20.41 保留原版雷达的平面投影，并为补点填写目标沿本人上方向的有符号高度。原版 `UMG_MinimapNode` 用这个值决定职业图标相对落点的位置、显示大圆还是小圆，以及是否画高度线；同一拍刷新，所以目标移动或者本人翻滚不必重新标记。19.20.40 的零售日志中，敌人已有三维坐标和正确的图标，但这个高度字段一直是零。

零售版在 MiniFarm 的美术层放置了一个弹药箱，在 Warehouse 的两种美术层中各放了两个。地图上的 `SupplyPoint_BP` 给自己的静态标记组件开启 `bLocalMarked`，标记类型是 `InteractiveObj`，小地图纹理是原版 `Tex_UI_MiniMap_Icon_AmmoCase`。它和敌人的侦察标记使用不同的名单。在 19.20.38 的 MiniFarm 普通局里，弹药箱已进入本机的 `LocalMarkedArray`，原生补给提示也可见，但当前玩家的小地图始终没有弹药图标。

现在小地图会读取本机标记名单中仍有效的补给点；如果名单尚未同步，也接受同一视口已经显示的原版补给提示。两者指向同一个弹药箱时只画一次。它使用箱子自己的纹理、标记位置和当前雷达的投影，不要求玩家先对准箱子。原版画布已有对应图标、箱子不再对本机公开、离开雷达范围、失去信号或角色死亡时会撤回补点。此逻辑只认有原生本地标记的实际 `PBSupplyPoint`，不搜索世界 Actor，不为别的交互物或训练用箱子虚构图标。

玩家按原版标记键（默认 `Z`）指中敌人时，游戏会在当前角色上记录一个 `MarkActor`。雷达核对标记者是当前玩家、目标是存活的敌方角色，再取目标此刻的位置和原版职业图标。标墙或地面仍然是位置提示，不产生敌方图标。标记被替换或失效时，即使旧对象引用还在，雷达也不再使用它。[实现](MarkedHeadRadar.hpp)

侦察探针和本方共享标记使用游戏复制给本机的名单。每份名单只认对应的有效标志和来源；只要目标仍在雷达范围内，玩家转身或视线被挡不会提前撤点。本人手动标记与探针同时指向同一敌人时只画一个图标；最后一个有效来源撤标才移除。没有已确认来源时，只有当前视口中确实可见、未遮挡的本方敌人头标可以补点，不搜索地图上的角色。

修正仅在工具箱打开的本机 PvE 中启用，核对游戏复制给客户端的难度模式、当前角色和本地控制器。它使用当前雷达的距离和投影边界（零售默认：5,000 个世界单位；水平 UV 0 至 1，垂直 UV 0.125 至 0.75）。雷达无信号、玩家死亡、离开视口或目标超出边界时会移除补点；原生雷达接手后不重复绘制。[受控界面测试](tests/result.json) · [玩家标记与侦察探针的零售实局](../../../docs/BRT-LOCAL-RADAR.md)

两份补丁接在同目录的社区角色界面回调和相应的 Visual Studio 项目中。先应用社区麻雀瞄环修正，将本目录的头文件放在同一个回调源文件旁，再应用相应分支的雷达补丁。工程会编译原版的两个 UMG 实现，以调用实际 Blueprint 的画布和刷新方法。[V0.8.4 补丁](v084.patch) · [拆分版补丁](split.patch)

验证脚本在一个新目录里应用两层补丁，编译完整客户端业务文件和两个具体 UMG 翻译单元，检查业务对象引用和 SDK 对象定义的符号，并合成静态库。行为回归运行相同的 C++ 修正和可控的本机界面对象，覆盖空捕获表、原生点接管、回收池、视口归属、距离、消标和死亡。[编译验证](verify-source.ps1) · [行为回归](tests/verify.ps1)

本机 PvE 的 `Saved/Logs/BRT-local-ui.log` 只在本人角色进入支持的房间后打开。每项仅记录第 1 次和第 16 次，共不超过 58 行。雷达记录原有公开头标、投影、原生点和画点分支；补给分别记录本地标记、原生图标接手和补点；挂载记录本人左右肩选择、归属和第一人称组件收集；麻雀瞄环记录识别、隐藏和恢复。不另遍历角色，不记录目标身份、坐标、按键或令牌。这些是整场累计的处理次数，不能据此判定玩家在画面上看到了修复。
