# 头顶标记、弹药箱和雷达点的回归测试

在 Windows 的 Visual Studio 2022 C++ x64 环境中运行 `./verify.ps1`。脚本把当前 `MarkedHeadRadar.hpp` 复制到独立输出目录，编译两个程序。两者使用相同的有效控件、回收池、所属玩家和地图状态。对照程序保留原有节点并省略新增回调，候选程序直接执行生产头文件里的绘制、接管、撤回和角色生命周期逻辑。每次运行会留下头文件哈希、逐项日志和汇总 JSON。[运行脚本](verify.ps1) · [场景与断言](radar.test.cpp)

本次雷达专项共执行 89 项检查，候选通过 89 项。完全省略补点回调的对照通过 48 项、失败 41 项；它不是发布版 live43。新增场景分别覆盖本人手动标敌、探针和本方共享标记在转身或遮挡后的显示、不同来源不能互相延长时间、标墙或队友不产生敌方图标，以及失效时的清理。[候选与空回调的结果](result.json) · [与 live43 的零售实局对照](../../../../docs/BRT-LOCAL-RADAR.md)

弹药箱场景使用零售 `SupplyPoint_BP` 的静态本地标记配置，检查没有敌人、头标缺席、玩家转向别处时仍使用正确的补给纹理。原生图标接手、离开雷达范围、目标隐藏、标记撤销、失去信号、死亡、换世界和离开本机 PvE 时都要清理。相同箱子同时经名单和 HUD 提供时只留下一个控件。原有敌人标记测试继续覆盖本方标记、过期捕获、遮挡、多个目标、回收池与视口归属。此套测试验证本地 HUD 的状态变化；此前敌方头标的零售实测见 [live38 记录](../../../../docs/BRT-LIVE38.md)。
