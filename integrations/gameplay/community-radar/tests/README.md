# 头顶标记和雷达点的回归测试

在 Windows 的 Visual Studio 2022 C++ x64 环境中运行 `./verify.ps1`。脚本把当前 `MarkedHeadRadar.hpp` 复制到独立输出目录，编译两个程序。两者使用相同的有效控件、回收池、所属玩家和地图状态。对照程序保留原有节点并省略新增回调，候选程序直接执行生产头文件里的绘制、接管、撤回和角色生命周期逻辑。每次运行会留下头文件哈希、逐项日志和汇总 JSON。[运行脚本](verify.ps1) · [场景与断言](radar.test.cpp)

live38 共执行 48 项检查，原生标记已复制、头标控件缺席时也有覆盖。未接入补点逻辑的对照通过 23 项，主要覆盖原本就不应出现节点的情况。候选通过 48 项。头顶已有有效标记且原生地图为空时会补点。原生点出现后，候选撤回自己绘制的点。回收池中、隐藏、透明、已失效或属于另一玩家的节点不会阻止补点。目标遮挡、超距、死亡或标记过期后会撤点。两个独立标记可同时显示，各自可独立撤回。此处验证本地 HUD 的状态变化，零售客户端的画布验收见 [live38 记录](../../../../docs/BRT-LIVE38.md)。[本次结果](result.json)
