# 按干员取本人出生配装

适用于 BRT 托管档案服务。在专服已经确认玩家和干员、还没生成角色的阶段，不再要求它先猜主枪和副枪。旧的三字段请求仍用于局内明确手选的主副枪。

| 房间给出的选择 | 档案服务返回 |
| --- | --- |
| `{role: "PROBE"}` | 本人探针的主副枪、全套部件与涂装、挂饰、左右挂载、近战、机动，以及本人明确保存的角色外观 |
| `{role: "PROBE", primary: "...", secondary: "None"}` | 本命手选的枪及其个人部件；明确空槽保持空。两把枪必须都报出 |

已认证的普通房间使用 `member.prepareSaved(life, role)`，等价于发送带 `connectionId`、`life` 和 `selection: {role}` 的 `prepare` 请求。首次成功后，同一连接同一命的重复请求返回当时的快照；重试不会混入军械库后续改动。相同生命号改换请求方式或干员会被拒绝；显式存有无效枪时不会投递原厂枪。下一命才取新的档案。已有房间的认证与离房规则不变。

签名登记的本机房主也可以在原 `birth-plan` 查询中只给干员名。这个查询只读当时的方案，不占用生命号，不表示角色已经装备。普通固定房间不提供该查询。

[维护差异](role-only.patch)以冻结的 19.20.33 档案服务和房间 SDK 为基准；正式工作树的 `room-spawn.cjs` 由 Rust 工具箱嵌入档案运行环境。角色外观、部件和挂载沿用现有个人档，没有改默认表、原始存档或游戏文件。Steam 零售普通房尚未观察到它在部署或出生时请求并应用这份配装。

[协议回归](protocol.test.cjs)使用正式装备定义和两个内存账号，在 HTTP 层验证跨命更新、同命重试、新旧选枪方式、卸空、坏档及账号隔离。运行：`node protocol.test.cjs <托管档案服务目录>`。另与实际军械库回包核对 6 名干员、36 个装备栏、120 个枪械配件槽和 3 套已保存的角色服装；两把偏离原厂型号的副枪也正确返回。
