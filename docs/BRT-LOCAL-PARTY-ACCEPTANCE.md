# 19.20.43：三端本机匹配与复活换装

这里的“三端”指三个独立的托管大厅进程、三个测试账号和三条实际的原生大厅 RPC 连接。没有使用玩家的 Steam 身份，也没有三个零售客户端出生记录。

队长创建队伍，两名队员登记到各自的席位。队长在原生播放列表选普通 OSS，队员分别点这张票的确认卡。测试检查三个大厅收到相同队伍 ID、票号和游戏地址；确认未齐不分房。专服从 BRT 隔离安装启动，必须报告 OSS、正确模式、正在监听，并通过进程和 UDP 归属检查。队长领取地址后离开大厅，队员仍可领取地址。验收结束时关闭专服，并实际重新绑定该端口。

本机档案桥仅在显式登记的子进程与其父进程通过 IPC 通信时启用。普通工具箱启动保持原有单人大厅；回环地址只适用于本机联测。该桥不开放档案或控制服务，也没有把回环地址用于跨设备分房。跨设备还需要把每位成员的已认证游戏通道绑定到同一票据，并验收到场人数和出生角色。

复活换装这次修正的是两套装备 ID。零售角色范围里是 `PROBE_GSW-DMR` 和 `PROBE_TAC-EMP`，武器和肩挂定义表里是 `GSW-DMR` 和 `TAC-EMP`。原生预订确认及干员范围验证仍用前者，查蓝图用后者。不同干员、未知行、无确认、失去角色归属或窗口到期均不能套用。编译生产换装处理函数的 C++ SDK 夹具检查同一角色上的主枪和肩挂、原弹量、重复确认、卸下装回和 5 秒边界。夹具不模拟 UE 网络复制，不能替代零售客户端画面。

复验入口：[三大厅和真实专服](../tools/test-three-local-lobbies.cjs)、[零售定义表和生产换装处理函数](../tools/test-respawn-applied.ps1)。零售现场剩余步骤：自然复活后在 5 秒内选择不同主枪和肩挂，记录客户端和专服各自同一角色实例的前后状态；重复确认和超时再点都不能补弹或重生。
