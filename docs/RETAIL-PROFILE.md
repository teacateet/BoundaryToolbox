# Steam 零售版：军械库和对局的边界

适用于已核对的 Steam Build `14530908`、社区 `V0.8.4` 和 BRT 本机托管档案。问题反馈 QQ 群：**1048069240**。

| 游戏读取时机 | 工具箱处理 | 不能由此推断的事 |
| --- | --- | --- |
| 社区客户端启动时 `GET /api/loadout/<示例账号>` | 识别社区客户端的固定请求。用 Windows 的回环连接归属、预期游戏程序、已登录的档案会话和当前 Steam 账号确认同一个人。不能唯一确认即拒绝，不选择最后登录的人。 | 社区发行代码只在这一处用六个槽刷新陈列角色。它没有在每次出生重新应用武器配件。 |
| 原生大厅读取 `GetPlayerArchiveV2` | 按角色和枪械保留各自配件、皮肤、涂装、准星和挂饰；左右挂载、近战和机动是独立槽。新账号只读原厂装备；个人档只存过一名干员时，其余普通干员补各自默认值，不写入存档。 | 回包里有镜子、机匣涂装或弹匣，不表明角色已经生成这些部件。不要给所有人写同一套默认装备。 |
| 已登记的本机房读取 `QueryAssetsInMatch` | 给已登录房主返回六名普通干员各自允许的枪、挂载、近战和机动目录；拒绝其他账号和已结束房间。 | 这个原生消息没有已装备的左右槽、武器配件、涂装和生命编号。 |
| 社区专服在房主首次登录时预订选角装备 | 已编译的两个社区源码版本在正常登录业务中，按所属房主为六名干员各提交一次主枪、副枪、左挂载、右挂载、近战和机动。工具箱允许将这六次调用完成的原文写入房间日志。 | 原作预订方法不返回是否接受。现有玩家录像在第一次选角时显示了原厂装备。 |
| 本机房请求首次选角或本条生命的出生配置 | 首次登录且尚无个人文件的本机房主可以选择六名普通干员。只保存过部分角色时优先使用个人配置，其余补各自的出厂槽。按房间、账号和生命核对权限。 | 出生配置包含武器部件、单件与整枪外观，须在当前玩家生成的实体上应用。 |

`legacy-client*.test.cjs` 检查错进程、歧义、断开、切换账号、全新/部分/损坏档、显式卸空，以及原生档案与社区六槽回复。`room-spawn.test.cjs` 检查两间房、不同玩家和重生后仍保留各自选择；`retail-match-catalog.test.cjs` 及 `release-menu.test.cjs` 验证对局目录及拒绝分支。`verify-menu.cjs --embedded` 校验正式可执行文件中组件的原始字节。

玩家发布门槛：同一条零售角色生命实际使用保存的配装；切换或死亡后挂载模型与专用准星收起；冷却结束后钩索能再次牵引；死亡后成功换人；对已标记和符合探测条件的目标显示雷达点。没有这些结果时保留旧包冻结状态。
