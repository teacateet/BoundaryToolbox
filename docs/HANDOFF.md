# Boundary Resurrection Toolkit 协作交接

本项目运行 Steam 原版《边境》。Rust/Slint 工具箱负责启动与配置，ProjectRebound 管理对局，BoundaryMetaServer 提供角色与配装档案。

## 局内七项的排查结论与本机联调（2026-11-24）

live37 经玩家两场普通局，枪配件和涂装已带入。之后用本机联调（自己起专服和客户端，在进程里读对象、调函数）查了首命只有手臂、钩索、死亡 Esc、雷达、挂载挡脸、占点、泄压设施和舱门。首命、雷达、挂载、占点四项查到了原因，首命的修法已在联调里验证；钩索、死亡 Esc、交互三项原因未明。没有安装新组件，没有重新打包。

逐项结论、依据和缺口在局内交接顶部。联调方法：[dev-rig](../integrations/gameplay/dev-rig/README.md)。首命修法：[community-first-loadout](../integrations/gameplay/community-first-loadout/README.md)。

## 19.20.32 内部构建，局内修复进行中

冻结 19.20.32 之后的维护源码已按整个角色和装备目录处理。这些改动不在旧 ZIP 里。正常房间的 6 名干员存在 55 组合法角色与枪械搭配，按主、副槽分别核对。机匣来自普通、活动与困难变种的原作表，27 种挂载的本机视图走同一归属规则。服装、服装颜色、臂章与头饰也跟同一玩家的出生配置走。原作服务端尚未订阅完整的出生库存，客户端也未加载 HUD 改动，因此不发行新玩家包。[维护源码和验证边界](../integrations/gameplay/README.md) · 房间接入排查

本机档案服务现将同枪分次提交的瞄具、弹匣和涂装合并保存。MiniFarm 冷启动先确认排队，游戏端口就绪后提供地址。出生配装接口已在普通档案服务和 C++ 接收端之间读回两名合成玩家各自的装备，当前 Steam 客户端仍需在对局里接入并验证。

玩家的 19.20.31 录像显示，选角初始为蜂巢和空槽，军械库里的红色 FOP 和微型红点在出生后变成白灰枪身与机械照门。麻雀准星跨过切枪和死亡画面。重新开放测试时需要确认选角和出生均保留配装、收起挂载后不挡视线、钩索在同一生命中能够再次牵引。[内部构建记录](../target/release-audit-19.20.32/receipt.json) · [源码联测](../integrations/spawn/RESULT.md)
