# BRT 19.20.38：死亡换人和建房取消

本次验证使用 Steam《边境》Build 14530908。玩家报告的是场景继续播放、键盘和鼠标却不再控制角色。普通难度 MiniFarm 的隔离对局复现了其中一种情况：选角页已关，专服已确认 PROBE，客户端却停留在死亡状态，没有可控制的角色。只看进程、菜单或输入锁，都不能证明换人完成。

## 死亡后重新部署

客户端确认选角时，死亡控制器可能尚未进入可复活状态。社区专服还有独立的重生许可：阵亡会关闭它，选角确认本身不一定重新打开它。现在客户端保留本次部署，等控制器就绪后提交一次原生请求。若玩家仍无角色，本机 PvE 专服会在核对房主、连接、死亡次数、干员、回合和重生资格后，调用一次游戏模式的原生复活流程。若已经出生、换了连接或回合结束，就不再处理。客户端等到本人接管存活的第一人称角色后恢复移动和视角，不夺取其他弹窗的焦点。

在同一场 MiniFarm 普通局中，玩家连续两次自然阵亡后换人，完整顺序是 **PEACE → PROBE → PEACE**。每次都通过游戏输入接口发送 Esc，调用当前可见角色卡片和部署按钮。专服确认对应角色实际出生；测试脚本没有额外发复活指令。随后向同一角色发送 W 和水平转向输入：

| 换入角色 | W 后位移（地图单位） | 水平朝向变化 | 游戏、移动、视角输入锁 |
| --- | ---: | ---: | --- |
| PROBE（第二条命） | 161.2 | 4.55° | 均已解除 |
| PEACE（第三条命） | 205.8 | 4.55° | 均已解除 |

实机运行在独立的 Windows 桌面。Esc 和 W 通过游戏输入接口发送，转向通过控制器输入接口发送，没有使用前台或物理键鼠。观测构建与玩家 DLL 使用相同的死亡菜单、房主复活及接入代码；观测构建另带测试接口，并连接独立端口的本地档案服务。玩家 DLL 不含测试接口。死亡菜单受控回归通过 76 项，覆盖菜单早关、确认晚到、控制器晚就绪、取消、其他弹窗及非本人角色。单图后台实测不能代表每张地图、每次时序或真实跨电脑输入。

## 建房与联机

- **真实专服：** 在隔离游戏目录中启动 PvP 房，等启动器创建后取消，确认房间所有权记录和 UDP 监听都已释放。用同一端口重新开启 Warehouse，确认专服已监听，然后正常关房。
- **失败返回：** 在离屏界面让另一个 UDP 服务占用端口，验证建房显示失败、点「返回」能清除错误，原服务仍然能收包。建房等待期间，取消按钮也能接收点击。
- **异地组网：** 用只接收连接、不回复注册的本机 TCP 服务验证 VNT 等待注册时能够取消并重试；用户取消和注册失败同时发生时，不再弹出误报。没有用两台电脑实测异地联机。

房主、同一局域网队友和异地队友的步骤见[玩家指南](PLAYER_GUIDE.md#和朋友一起玩)。首命持枪与连续出钩是[上一版的实机验收](BRT-LIVE41.md)；本版没有把它们列为重新实测的结果。
